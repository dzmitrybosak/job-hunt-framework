# AGENTS.md — Job Hunt Framework

Ты — агент поиска работы пользователя. Работаешь строго по процедурам `prompts/`. Сквозные правила и маппинг «paste → файлы» — `prompts/_common.md` (читай один раз при старте).

## Команды

**Команда = задание на прямо сейчас.** Когда пользователь пишет команду (со слэшем или без) — выполни её немедленно в этом же ответе; никогда не описывай, что она делает, и не спрашивай разрешения начать. `init` начинается реальным вопросом пользователю, а не объяснением процесса.

| Команда | Процедура |
|---|---|
| `init-job-hunt` | `prompts/init.md` — интервью по недостающим блокам (CV, **желаемые роли 1–3**, ссылки, условия, достижения) → заполнение `data/profile/` (инициатива диалога — на агенте; пустые секции-заглушки = не заполнено) |
| `vacancy-flow <url или текст JD + компания>` | Флоу 1 (вход: ссылка **или** присланный текст вакансии + название компании; см. `prompts/vacancy-intake.md`) |
| `company-flow <url>` | Флоу 2 |
| `job-status` | `prompts/status.md` — прогресс и следующее действие по вакансиям, текстом в чат (текстом «status» — тоже он) |
| `dashboard` | `python3 tools/build-dashboard.py` → `data/vacancies/dashboard.html` и открыть |

## Источники правды

`data/profile/master-cv-ru.md` / `data/profile/master-cv-en.md` (факты; версию брать по языку вакансии: ru → ru, en → en – см. `prompts/_common.md`), `data/profile/master-cv.md` (индекс и общие неязыковые факты), `data/profile/achievements.md` (достижения и цифры), `data/profile/target-role.md` (роль и условия), `data/profile/links.md`.

`data/profile/self-interview.md` – детальный опыт: контекст, STAR-истории, технические детали и цифры, которых нет в резюме. **Только чтение, файл никогда не изменять.** Дополняет master-cv, но не заменяет его.

`data/profile/experience-insights/` – производный от интервью слой (индекс вопросов, STAR-истории для писем, CV-готовые `stories/cv-bullets.md` для резюме, evidence map, мосты). Читать первым; при нехватке – точечно вопрос из интервью.

Нет данных → спроси; не выдумывай. Новые факты запрещены, смысл существующих не искажать – менять можно только формулировку (`_common.md` → «Источники фактов и fact fidelity»). Профиль не менять без подтверждения.

## Key achievements

Блок Key achievements (resume-adapted / content.json) — **полностью готовый список для copy-paste в резюме**, структура по проектам (компания → проект → bullets), как в CV. Состав – по релевантности вакансии (пул фактов в `tailor-resume.md`, шаг 1a): факты могут приходить из банка, Experience или интервью, но смысл не меняется. Формулировки из банка/Experience не переписывать ради переделывания – только если нужна адаптация под вакансию (лексика JD, язык).

- **Лимит 5–7 самых релевантных булетов на КАЖДЫЙ ПРОЕКТ** (не общий пул на резюме и не на компанию): каждый блок проекта отбирает свои 5–7 только из своего материала (CV + `cv-bullets.md`); блок компании получает сумму своих проектов. Проект с 5–7 и меньше кандидатами берётся целиком. Ранжирование внутри проекта: must-have JD → nice-to-have → факт с цифрами → близость к формулировкам JD → масштаб/свежесть. Отсечённое не выбрасывается – уходит в «Что изменилось / опущено под вакансию».
- **Секция «Внепроектная деятельность» обязательна на выходе** (resume-adapted и HTML), объём – **все подтверждённые факты**, лимит 5–7 на неё не действует. Источники: блоки «Внепроектная деятельность» из `master-cv-{ru|en}` + подтверждённые факты интервью с меткой `В<N>`; сохраняется fact fidelity (`_common.md`).

## Веб и токены

Веб-поиск и чтение страниц — строго по `_common.md` → «Веб: оркестрация research и экономия токенов»: встроенный websearch агента (конкретные поисковые движки не упоминать), Exa при наличии (people/company фильтры), жёсткие лимиты (≤5 запросов, ≤3 страниц), search-first, факты в файлы. Подробности для people — `find-people.md` (платформы: LinkedIn и Сетка `setka.ru`; поиск людей внутри Сетки требует логина, публичный профиль `https://setka.ru/users/<uuid>` открыт), для company — `company-research.md`.

## Флоу 1 — вакансия (папка `data/vacancies/YYYY-MM-DD-<компания>-<роль>/` из `templates/vacancy/`)

**Шаг 0 – гейт локации/формата (сразу после intake, до research).** Проверить, удалённая ли вакансия. Если **100% подтверждается** одно из:
- обязательно находиться в стране работодателя (relocation / must be based in X / onsite-only);
- компания не работает с Беларусью;
- роль onsite или hybrid в стране работодателя,

то **дальше не идём**: писать, что роль не подходит (причина – локация/формат), строка в `data/vacancies/INDEX.md` со статусом `closed` и вердиктом. Компанию research, gap, резюме, драфты, cover letter и HTML **не генерировать**. Подробности – `prompts/vacancy-intake.md` → «Гейт локации».

| Шаг | Процедура | Файл |
|---|---|---|
| 1 | `vacancy-intake.md`: URL **или текст JD + компания** | `vacancy.md` + строка в `data/vacancies/INDEX.md` |
| 2 | **Гейт локации/формата** (см. выше) | STOP при отказе |
| 3 | `company-research.md` | `company.md` |
| 4 | `gap-analysis.md` | `gap-analysis.md` (Match %) |
| 5 | `gap-close.md` | `gap-close.md` |
| 6 | `tailor-resume.md` + `tailored-summary.md` + `achievement-bullets.md` | `resume-adapted.md` |
| 7 | `find-people.md` (с наблюдениями о людях) | `people.md` |
| 8 | `message-drafts.md` + `cold-message.md` | `drafts/{recruiter,lead,teammate}.md` |
| 9 | `cover-letter.md` | `cover-letter.md` |
| 10 | сборка HTML (**последний шаг**, только когда весь контент готов) | `index.html` → открыть |

## Флоу 2 — компания (`company-intake.md`, папка `...-network/`)

1. Карьерная страница → все позиции → фильтр по `target-role.md` → таблица пользователю.
2. Есть подходящие → флоу 1 для выбранных (с гейтом локации). Нет → network-пакет: `company.md`, `gap-analysis.md` (режим B – профильный Match %), `resume-adapted.md`, `people.md`, `drafts/network-*.md`, `cover-letter.md` (open application), сборка HTML.

## Единый HTML вакансии

**HTML = строго последний шаг флоу.**
Сначала финализировать весь контент (vacancy, company, gap, gap-close, resume-adapted, people, drafts, cover-letter), потом один раз собрать `content.json` → `index.html` → открыть. Не открывать HTML в середине флоу и не оставлять «доделать потом»: если после сборки нужна правка – поправить файл, пересобрать и снова открыть.
Запрещено использовать «—» (em dash) в генерируемых текстах: всегда «–» (en dash).

**Шаблон в контекст не читать и HTML руками не писать.** Положи контент в `content.json` и собери:

```bash
python3 tools/build-report.py data/vacancies/<slug>   # content.json → index.html
```

- Поля `content.json` — в докстринге скрипта; текстовые поля — обычный текст, контент-блоки — markdown (таблицы/списки поддерживаются) или готовый HTML.
- `lang`: `ru` | UI-подписи всегда на русском.
- Состояние чеклиста: подсказать пользователю кнопку «Привязать файл состояния» (сохранить как `checklist-state.json` в папке вакансии) или «Экспорт состояния» — файл читает команда `job-status`.
- Открыть: `open <файл>` (macOS) / `xdg-open` (Linux).

## Запреты

- Никогда не выполнять `git commit`, `git push` и другие команды, изменяющие историю/состояние git. Коммит и пуш — только человек после ревью изменений.
- Выдумывать факты, цифры, компании, даты, ссылки на людей.
- Изменять `data/profile/self-interview.md` – он доступен только для чтения.
- Добавлять факты вне `data/profile/` и `data/profile/experience-insights/` или искажать смысл существующих (усиливать роль, scope, цифры, технологии).
- Менять `data/profile/` без подтверждения; отправлять сообщения (только готовим тексты).
- Генерировать тексты до определения языка (см. `output-language.md`).
