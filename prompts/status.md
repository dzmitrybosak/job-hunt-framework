# Prompt: status — сводка «что делать дальше»

Команда `status`. Показывает по каждой активной вакансии прогресс и **следующее действие**. Вакансии с полностью пройденным чеклистом (10/10) в сводку не включаются.

## Источники данных

1. `data/vacancies/INDEX.md` — список вакансий, статусы.
2. `data/vacancies/<slug>/checklist-state.json` (или `<slug>-checklist-state.json` в `~/Downloads`, если пользователь делал экспорт) — состояние чеклиста: `{status, checks, dates}`. Пишется HTML-файлом вакансии (кнопка «Привязать файл состояния» — автозапись; «Экспорт состояния» — ручной файл).
3. Сегодняшняя дата.

## Шаги

1. Найти все папки вакансий с `index.html` и подтянуть их state-файлы (папка вакансии → `~/Downloads`). Последний изменённый файл при конфликте.
2. Для каждой вакансии вычислить:
   - **прогресс:** n/10 отмеченных пунктов;
   - **следующее действие:** первый неотмеченный пункт чеклиста по порядку (его название) — это базовый next action;
   - **дедлайны по датам** (если проставлена дата отклика D1 и соответствующие пункты не отмечены):
     - D1 + 5–7 рабочих дней → окно первого follow-up (пункт 8);
     - сегодня > D1 + 7 рабочих дней, пункт 8 не отмечен → «просрочен первый follow-up»;
     - D1 + 10–14 дней → окно финального сообщения (пункт 9);
     - сегодня > D1 + 14 дней, пункт 9 не отмечен → «просрочено финальное сообщение»;
     - пункт 8 отмечен и прошло 1–2 рабочих дня → «пора финальное сообщение».
3. Отфильтровать: **10/10 — не показывать** (кроме строки-сноски «N вакансий завершены»).
4. У кого нет state-файла — строка с честной пометкой: «нет данных чеклиста — открой HTML, кнопка “Привязать файл состояния” или “Экспорт состояния”»; next action оценить по статусу INDEX (`new` → начать обработку, `applied` → проверить чеклист).
5. Отсортировать: просроченные сверху, потом по ближайшему окну.

## Формат вывода (таблица в чат)

| Компания / Роль | Прогресс | Следующее действие | Окно / дата |

Плюс строкой итог: сколько активных, сколько завершено, что горит.

## Правила

- Не генерировать HTML — статус выводится в чат.
- Даты считать по календарю пользователя; «рабочие дни» — без сб и вс.
- Состояние чеклиста не переписывать и не «догадываться» за пользователя — только читать.
