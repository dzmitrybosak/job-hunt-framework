# Prompt: status – сводка «что делать дальше»

Команда `status` (скилл `/job-status`; текстом «status» тоже). Показывает по каждой активной вакансии прогресс и **следующее действие**. Вакансии с полностью пройденным чеклистом в сводку не включаются (10/10 в режиме application, 8/8 в network).

## Источники данных

1. `data/vacancies/INDEX.md` – список вакансий, статусы.
2. `data/vacancies/<slug>/checklist-state.json` (или `<slug>-checklist-state.json` в `~/Downloads`, если пользователь делал экспорт) – состояние чеклиста: `{status, checks, dates}`. Пишется HTML-файлом вакансии (кнопка «Привязать файл состояния» – автозапись; «Экспорт состояния» – ручной файл).
3. Сегодняшняя дата.

## Шаги

1. Найти все папки вакансий с `index.html` и подтянуть их state-файлы (папка вакансии → `~/Downloads`). Последний изменённый файл при конфликте. Заодно определить режим: `mode` из `data/vacancies/<slug>/content.json` (файла нет → application).
2. Для каждой вакансии вычислить:
   - **прогресс:** n отмеченных **видимых** пунктов из 10 (application) или из 8 (network: пункты «Отклик» и «Сохранить описание вакансии» скрыты и не считаются);
   - **следующее действие:** первый неотмеченный видимый пункт по порядку, называть его **текущим названием**, не номером (в network нумерация другая: первый follow-up отображается как пункт 6, финальное сообщение – как 7) – это базовый next action;
   - **дедлайны по датам:** якорь D1 – дата «Отклик» (application) или дата «Отправить рекрутеру персонализированный запрос» (network); если она проставлена и соответствующие пункты не отмечены:
     - D1 + 5–7 рабочих дней → окно первого follow-up («Первый follow-up рекрутеру»);
     - сегодня > D1 + 7 рабочих дней, первый follow-up не отмечен → «просрочен первый follow-up»;
     - D1 + 10–14 дней → окно финального сообщения («Финальное вежливое сообщение»);
     - сегодня > D1 + 14 дней, финальное сообщение не отмечено → «просрочено финальное сообщение»;
     - первый follow-up отмечен и прошло 1–2 рабочих дня → «пора финальное сообщение».
3. Отфильтровать: **все видимые пункты отмечены (10/10 или 8/8) – не показывать** (кроме строки-сноски «N вакансий завершены»).
4. У кого нет state-файла – строка с честной пометкой: «нет данных чеклиста – открой HTML, кнопка “Привязать файл состояния” или “Экспорт состояния”»; next action оценить по статусу INDEX (`new` → начать обработку, `applied` → проверить чеклист).
5. Отсортировать: просроченные сверху, потом по ближайшему окну.

## Формат вывода (таблица в чат)

| Компания / Роль | Прогресс | Следующее действие | Окно / дата |

Плюс строкой итог: сколько активных, сколько завершено, что горит.

## Правила

- Не генерировать HTML – статус выводится в чат.
- Даты считать по календарю пользователя; «рабочие дни» – без сб и вс.
- Состояние чеклиста не переписывать и не «догадываться» за пользователя – только читать.
