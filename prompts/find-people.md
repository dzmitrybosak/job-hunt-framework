# Prompt: поиск людей

**Вход:** `vacancy.md` (компания, роль), `company.md` (кто в команде уже выяснен), `profile/links.md`.
**Выход:** `people.md` в папке вакансии.

## Кого искать (по приоритету)

1. **Hiring manager** на эту роль (eng manager / iOS lead / head of mobile). В network-режиме (флоу 2, вакансии нет) — потенциальный HM: iOS/mobile lead или eng manager мобильной команды.
2. **Рекрутеры** компании (tech recruiter, talent acquisition), особенно ведущие iOS/мобильный найм.
3. **iOS lead / mobile lead**.
4. **Члены iOS-команды** (2–4 человека) — для тёплого контакта / реферала.

## Источники

Приоритет: **LinkedIn** (глобальные компании) → **Сетка** (`https://setka.ru`, RU/CIS и русскоязычные HM/рекрутеры) → карьерная страница (иногда имена HM) → инженерный блог/конференции (спикеры) → GitHub org → DOU/Glassdoor → Twitter/X.

**LinkedIn** – поиск по компании + ролям; профили и ленты не открывать (нужен логин), работать по сниппетам.

**Сетка (`https://setka.ru`)** – профессиональная сеть для нетворкинга от hh.ru (IT, digital, креативные индустрии; аудитория в основном РФ/СНГ). Проверено 2026-10-30:

- **Поиск людей внутри Сетки без логина недоступен:** кнопка поиска на сайте открывает login-модалку, `/search?query=` редиректит на `/login`. Не тратить на это поисковые запросы и загрузки.
- Искать через websearch по домену: `<компания> <роль> setka.ru`, `site:setka.ru <компания>`. Профили индексируются (`https://setka.ru/users/sitemap.xml`), сниппет уже даёт имя + должность.
- **Публичный профиль `https://setka.ru/users/<uuid>` открывается без логина** и отдаёт: имя, headline/должность, «статус» (например «ищу работу»), город, «про меня» (about), «карьера» (компания + должность + даты), образование, посты. Это primary-страница – читать точечно, только нужные поля.
- URL профиля – только UUID, человекочитаемого slug нет → ссылку брать из выдачи, не конструировать и не угадывать.
- **Нет списка сотрудников компании:** страница компании (`https://setka.ru/communities/<uuid>`, список – `/communities/top-companies`) показывает посты и описание, но не людей. Значит Сетка – второй проход (верифицировать «человек правда в этой компании» + взять about/карьеру для персонализации), а не первичный поиск.
- Лучше всего работает для RU/CIS-компаний и русскоязычных рекрутеров/HM; для международных ролей первичен LinkedIn.

**Поиск и лимиты** (`_common.md` → «Веб: оркестрация research и экономия токенов»): websearch агента; если подключен Exa – `category: "people"` + `includeDomains: ["linkedin.com"]` (или `["setka.ru"]` для RU-прохода), готовые `summary`/`cache_id` брать как есть. Для людей в основном хватает **SERP-сниппетов** (имя, роль, компания, город, 1 фраза about). Не открывать LinkedIn-профили и ленты (нужен логин); не вытягивать «3 последних поста», если их нет в открытом доступе — в наблюдениях писать честно, на чём построена персонализация (роль, about-фрагмент, публичный факт). Лимит: 1 поисковый проход на роль (HM/recruiter/lead) + 1–2 открытых primary-страницы, не более (жёсткие лимиты `_common.md` действуют сверху); открытый профиль Сетки считается одной из этих primary-страниц.

## Персонализация (обязательный шаг перед драфтами)

Для каждого найденного человека собрать: about + 3 последних поста (или публичные детали работы) → записать в `people.md` в секцию «Наблюдения для персонализации». Без наблюдений cold message по `cold-message.md` не пишется. Если посты/about недоступны без входа — фиксировать наблюдение из сниппета (роль, рост, фокус) и помечать источник; не открывать закрытые страницы ради «полноты». **Сетка здесь полезнее LinkedIn:** её публичный профиль отдаёт «про меня», «карьеру» (компания + должность + даты) и посты без логина — брать наблюдения оттуда и помечать источник «Сетка, профиль».

## Правила

- Ссылки — только на реальные профили; проверять, что человек действительно в этой компании сейчас.
- Формат LinkedIn-ссылки — каноничный `https://www.linkedin.com/in/<slug>`; Сетка — `https://setka.ru/users/<uuid>` (только из выдачи, UUID не угадывать). В таблицах и в JSON указывать платформу, чтобы было видно, откуда взят профиль.
- Сетка: **не пытаться искать людей внутри сайта** (поиск и «нетворк» требуют логина) и не открывать её разделы, закрытые авторизацией; публичный профиль и пост открываются без логина – их можно читать точечно.
- Найдено 0 — так и написать, без выдуманных имён. Неполные данные не додумывать: нет имени/роли в сниппете — пометить «нет данных», не угадывать.
- Каждый найденный человек — с evidence-выдержкой (1–2 предложения) и URL источника; целые абзацы не цитировать.
- В конце `people.md` (и в ответе в чате) — JSON-блок со структурированными данными: `{"people": [{"name", "role", "company", "linkedin", "setka", "source_url"}]}`. Поле платформы, по которой профиль не найден, оставлять пустым, а не подставлять чужую ссылку.
