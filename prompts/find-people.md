# Prompt: поиск людей

**Вход:** `vacancy.md` (компания, роль), `company.md` (кто в команде уже выяснен), `profile/links.md`.
**Выход:** `people.md` в папке вакансии.

## Кого искать (по приоритету)

1. **Hiring manager** на эту роль (eng manager / iOS lead / head of mobile). В network-режиме (флоу 2, вакансии нет) — потенциальный HM: iOS/mobile lead или eng manager мобильной команды.
2. **Рекрутеры** компании (tech recruiter, talent acquisition), особенно ведущие iOS/мобильный найм.
3. **iOS lead / mobile lead**.
4. **Члены iOS-команды** (2–4 человека) — для тёплого контакта / реферала.

## Источники

LinkedIn (поиск по компании + ролям), карьерная страница (иногда имена HM), инженерный блог/конференции (спикеры), GitHub org, DOU/Glassdoor, Twitter/X.

**Поиск и лимиты** (`_common.md` → «Веб: оркестрация research и экономия токенов»): websearch агента; если подключен Exa – `category: "people"` + `includeDomains: ["linkedin.com"]`, готовые `summary`/`cache_id` брать как есть. Для людей в основном хватает **SERP-сниппетов** (имя, роль, компания, город, 1 фраза about). Не открывать LinkedIn-профили и ленты (нужен логин); не вытягивать «3 последних поста», если их нет в открытом доступе — в наблюдениях писать честно, на чём построена персонализация (роль, about-фрагмент, публичный факт). Лимит: 1 поисковый проход на роль (HM/recruiter/lead) + 1–2 открытых primary-страницы, не более (жёсткие лимиты `_common.md` действуют сверху).

## Персонализация (обязательный шаг перед драфтами)

Для каждого найденного человека собрать: about + 3 последних поста (или публичные детали работы) → записать в `people.md` в секцию «Наблюдения для персонализации». Без наблюдений cold message по `cold-message.md` не пишется. Если посты/about недоступны без входа — фиксировать наблюдение из сниппета (роль, рост, фокус) и помечать источник; не открывать закрытые страницы ради «полноты».

## Формат `people.md`

```md
# People — <Company> / <Role>
Дата:
Источники: [список URL]

## Hiring manager
| Имя | Роль | LinkedIn | Почему он/она | Заметки |

## Recruiters
| Имя | Роль | LinkedIn | Заметки |

## iOS lead
...

## iOS team (для тёплого контакта)
...

## Не найдено
- Hiring manager — не идентифицирован; альтернатива: ...

## Sources / машиночитаемый итог
{"people": [...]}
```

## Правила

- Ссылки — только на реальные профили; проверять, что человек действительно в этой компании сейчас.
- Формат LinkedIn-ссылки — каноничный `https://www.linkedin.com/in/<slug>`.
- Найдено 0 — так и написать, без выдуманных имён. Неполные данные не додумывать: нет имени/роли в сниппете — пометить «нет данных», не угадывать.
- Каждый найденный человек — с evidence-выдержкой (1–2 предложения) и URL источника; целые абзацы не цитировать.
- В конце `people.md` (и в ответе в чате) — JSON-блок со структурированными данными: `{"people": [{"name", "role", "company", "linkedin", "source_url"}]}`.
