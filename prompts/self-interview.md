# Prompt: self-interview → experience-insights

Разовый шаг (не часть каждого флоу): превращает подробное интервью в компактный производный слой, который читают остальные промпты. Запускается после добавления или обновления `data/profile/self-interview.md`.

**Вход:** `data/profile/self-interview.md` (**только чтение**), `data/profile/master-cv-{ru|en}.md`, `data/profile/achievements.md`, `data/profile/master-cv.md`.
**Выход:** `data/profile/experience-insights/`:
- `index.md` – тема → № вопроса → строки (навигация без чтения всего файла);
- `stories/star-stories.md` – истории в STAR + короткая версия (для cover letter и сообщений);
- `stories/cv-bullets.md` – те же истории в формате CV (структура master-cv, без нарратива) для Key achievements;
- `evidence/evidence-map.md` – случай → цифры → где уже есть в CV/банке;
- `gaps/bridges.md` – опыт из интервью, не отражённый в резюме, и чем он закрывает типовые гэпы;
- `topics/weak-notes.md` – слабые/неполные ответы и расхождения с CV.

## Шаги

1. Прочитать `data/profile/self-interview.md` целиком один раз. Зафиксировать структуру: части, номера вопросов, диапазоны строк.
2. Собрать `index.md`: для каждого вопроса – тема, номер `В<N>`, строки, 1–2 ключевых факта. Группировать по темам: трек, Swift/язык, concurrency, UIKit/SwiftUI, архитектура, данные/сеть, тестирование/CI, продукт/процесс, софт-скиллы.
3. Выделить истории в `stories/star-stories.md` – только те, где есть контекст, действие и результат. Формат:
   - **Название** (`В<N>`) – проект/домен.
   - **S/T:** ситуация и задача.
   - **A:** что делал именно я (субъект сохранять).
   - **R:** результат и цифра, если она есть в источнике; нет цифры – N/A.
   - **Короткая версия:** 1–2 предложения для cover letter / сообщения.
   - **Релевантные темы:** теги (concurrency, architecture, testing, product, communication...).
4. **CV-адаптация историй** → `stories/cv-bullets.md`. Каждая история из шага 3 конвертируется в bullets CV-формата:
   - **Привязка:** компания / проект / даты / название секции – из `data/profile/master-cv-{ru|en}.md`, не из интервью. Проект есть в CV – попадает в его блок; нет в CV (но есть в «Избранных проектах») – туда; нет места вообще – в секцию «Требует решения пользователя».
   - **Внепроектная деятельность:** факты вне проектов (митапы, демо, менторство, тренинги) привязывать к **работодателю**, а не к проекту – отдельная подсекция «Внепроектная деятельность» в RU и EN частях файла. Лимит 5–7 к ней не применяется (он только для проектных bullets при сборке резюме).
   - **Формат:** `[action verb] + [scope/scale] + [result with number] + [tool/method]`, factual-тон, прошедшие действия, 1 bullet = 1 достижение (1 история → 1–3 bullets).
   - **Убрать нарратив:** без «я научился», «тут был нюанс», «сначала… потом», без вводных и личных оценок. Остаются действие и результат.
   - **Смысл и цифры – дословно** из источника; при совпадении факта с CV приоритет у CV-формулировки. Источник в комментарии `<!-- В<N> -->`.
   - **Дубликаты:** факт уже в CV → не добавлять, а перечислить в секции «Уже в CV (не дублировать)».
   - **Языки:** RU-секция – базовая, после сборки показать пользователю на подтверждение. EN-секция – всегда помечена `DRAFT, не использовать без подтверждения пользователя`; до его явного «ok» в en-резюме не идёт. Между версиями не переводить самому без подтверждения.
5. Заполнить `evidence/evidence-map.md`: каждое число/масштаб из интервью → где оно уже подтверждено (`achievements.md` A-номер, `master-cv-{ru|en}.md`, `master-cv.md`) или «только интервью `В<N>`». Расхождения цифр между интервью и CV – в `weak-notes.md`, не выбирать самому.
6. Заполнить `gaps/bridges.md`: факты и истории, которые есть в интервью, но не выведены в резюме. Для каждого – какой типовой гэп он закрывает (например: legacy-миграция, тестирование, DI, модульность, продуктовые инициативы). Только формулировки, без усиления смысла.
7. Заполнить `topics/weak-notes.md`: ответы без конкретики/цифр, пустые вопросы, противоречия с CV, темы, где опыта нет. Это карта честных «нет данных», а не пробелы для выдумывания.
8. Показать пользователю сводку: сколько вопросов, сколько историй, какие новые факты найдены, где расхождения. RU-секция `cv-bullets.md` – на подтверждение, EN-секция – как draft. Производные файлы использовать после подтверждения.

## Формат `index.md`

```md
# Self-interview index

Источник: `data/profile/self-interview.md` (только чтение). Строки – по состоянию на <дата>.

## Трек и роль
- В1 – хронология компаний/проектов, строки 3–6
- В2 – переходы и мотивация, строки 8–35

## Язык и concurrency
- В7 – версии Swift, миграции, строки 109–113
...
```

## Правила

- `data/profile/self-interview.md` не изменять никогда – только читать.
- Новые факты запрещены: каждый пункт имеет источник `В<N>` (+ строки). Нет в источнике – не писать.
- Смысл не искажать: субъект, сила глагола, scope, цифры, технологии и даты сохраняются. Меняется только формулировка/структура.
- `stories/cv-bullets.md`: RU подтверждается пользователем, EN остаётся DRAFT до явного подтверждения. Форма CV-подобна, форма STAR – только для писем; не смешивать назначения.
- `cv-bullets.md` – полный пул возможных bullets; лимит 5–7 на проект применяется на этапе сборки резюме (`prompts/tailor-resume.md`), не при построении пула. «Внепроектная деятельность» идёт отдельной подсекцией по работодателю, в общий пул не смешивается.
- Если интервью противоречит CV – зафиксировать в `weak-notes.md` и спросить пользователя; не выбирать «удобную» версию.
- `experience-insights/` – производный слой: его можно пересобирать, исходник – нет.
- Файлы insights не попадают в HTML напрямую; они питают gap-analysis, gap-close, resume-adapted, summary, cover letter и драфты.
