### S1. Mock API / Demo Mode

**Источник:** В4 (56–74) · **Проект:** Access Management Platform (NDA2) · **Теги:** architecture, networking, testing, cross-team

- **S/T:** Приложению нужен Demo Mode – работа без интернета и реального бэкенда для тестирования и демонстраций.
- **A:** Около месяца проектировал архитектуру; изучал общие библиотеки заказчика, чтобы переиспользовать код. На базе существующих протоколов сетевого слоя разработал Mock API: запрос проходит тот же путь, что и обычный, но перехватывается и возвращает замоканный результат из JSON-файлов. Презентовал решение iOS-команде, затем синхронизировал с Android-разработчиками.
- **R:** Поддерживаются разные типы запросов (GET, POST и др.), новые эндпоинты добавляются легко; архитектура переносима в другие приложения заказчика; тестирование и демо не зависят от состояния сервера.
- **Короткая версия:** Спроектировал переиспользуемый Mock API поверх существующего сетевого слоя: приложение работает без бэкенда, а тесты и демо не зависят от сервера.
- **Факты:** ~1 месяц на проектирование; единый подход с Android.

### S2. Интерактивный виджет для управления устройствами

**Источник:** В5 (77–94) · **Проект:** Access Management Platform (NDA2) · **Теги:** SwiftUI, App Intents, Siri, product

- **S/T:** Пользователям было неудобно каждый раз заходить в приложение, чтобы открыть дверь или устройство.
- **A:** Предложил решение через виджеты, Siri и Shortcuts. Полностью спроектировал и написал виджет на новом тогда App Intents при малом количестве документации; реализовал связку виджет + Siri + Shortcuts; обеспечил мгновенную реакцию и связь с устройством в ограничениях виджета по памяти и времени.
- **R:** Через пару месяцев после релиза – более 1 000 000 успешных открытий через виджет; путь пользователя сократился до одного клика или голосовой команды; подход стал базой для развития управления устройствами.
- **Короткая версия:** Спроектировал и выпустил виджет на App Intents со связкой Siri + Shortcuts; более 1M открытий устройств через виджет за первые месяцы.
- **Факты:** 1M+ открытий; App Intents, WidgetKit, Siri, Shortcuts.

### S3. Техдолг виджета и его закрытие

**Источник:** В6 (97–99) · **Проект:** Access Management Platform (NDA2) · **Теги:** tech debt, modularization, architecture

- **S/T:** Чтобы не задерживать релиз виджета, часть логики пришлось продублировать в таргете виджета – координатор запросов на открытие/закрытие/актуацию устройств.
- **A:** Спустя полтора года, при переводе проекта на SPM-модули и Clean Architecture, логику вынесли и стали переиспользовать. Для UI-проблемы с неотзывчивыми таймлайнами и не меняющимся статусом актуации спроектировал optimistic behavior.
- **R:** Дублирование устранено, логика переиспользуется; архитектура optimistic behavior спроектирована (внедрение – отдельный шаг).
- **Короткая версия:** Осознанно взял техдолг ради релиза, а через полтора года закрыл его при модуляризации; спроектировал optimistic UI для виджета.
- **Факты:** ~1,5 года до закрытия техдолга; SPM + Clean Architecture.

### S6. Миграция completion handlers → async/await

**Источник:** В14 (205–223) · **Проект:** Access Management Platform (NDA2) · **Теги:** Swift Concurrency, migration

- **S/T:** Внутренняя библиотека нетворкинга и работы с устройствами была построена на completion handlers.
- **A:** Переводил её постепенно: оборачивал существующие методы с кложурами через `withCheckedContinuation`, новый код писал на async/await; заменил `switch result` на `do-catch`; добавил проверки отмены.
- **R:** Новый код использует async/await, старые части сохраняют совместимость; цепочки запросов стали линейнее.
- **Короткая версия:** Поэтапно перевёл внутреннюю библиотеку с completion handlers на async/await через `withCheckedContinuation`, сохранив обратную совместимость.
- **Факты:** без цифр (N/A).

### S8. Launch Coordinator на TaskGroup

**Источник:** В16 (240–245) · **Проект:** Access Management Platform (NDA2) · **Теги:** structured concurrency, performance

- **S/T:** На старте приложения нужно было собрать профиль, список устройств, конфигурацию секций главного экрана и уведомления.
- **A:** Запустил запросы параллельно через `TaskGroup`; ошибки второстепенных запросов (логи, баннеры) обрабатывал внутри `group.addTask` через do-catch, чтобы они не роняли группу. Для Siri выносил чтение KeyChain и сортировку в `Task.detached`, чтобы не задеть главный поток. Использовал кооперативную отмену и background-приоритет для аналитики.
- **R:** Время холодного старта сократилось до времени самого долгого запроса; главный экран показывается только после критичных данных.
- **Короткая версия:** Параллелил загрузку стартовых данных через TaskGroup с изоляцией ошибок; сократил холодный старт до самого долгого запроса.
- **Факты:** без цифр (N/A).

### S10. Mega Chips: Data Driven UI на Remote Config

**Источник:** В26 (375–395) · **Проект:** Property & Access Management Platform (NDA1) · **Теги:** system design, SwiftUI/UIKit, Remote Config, product

- **S/T:** Главный экран был перегружен legacy-кодом и сверстан в Storyboard; нужно было добавить динамический блок промо-чипов (5–10 элементов).

- **Короткая версия:** Спроектировал и защитил на Design Review модуль промо-чипов на Remote Config с fallback и state machine; блок стал инструментом монетизации.

### S17. Типизированные ошибки и централизованный unlogin

**Источник:** В11 (151–179) · **Проекты:** NDA1, NDA2 · **Теги:** error handling, architecture, security

- **S/T:** Ошибки приходили из разных источников (сеть, облако, доменные сервисы), а UI и сессия должны были реагировать предсказуемо.
- **A:** Базовая иерархия `NetworkError` (noData, unauthorized, serverError и т.д.) и `CloudError` с ассоциированными значениями (статус-код, внутренний код, дополнительные параметры). - **R:** Техническая ошибка превращается в понятное пользователю сообщение; истёкшая сессия автоматически возвращает на экран логина из любой точки приложения.
- **Короткая версия:** Выстроил типизированные ошибки (NetworkError/CloudError) с маппингом в UI и централизованный unlogin по истечении токена.
- **Факты:** без цифр (N/A).
